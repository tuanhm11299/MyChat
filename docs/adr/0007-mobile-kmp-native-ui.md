# 0007 — Mobile: Kotlin Multiplatform shared logic, native UI

Status: Accepted

## Context

We want native iOS and Android apps, to avoid writing networking/business logic twice, and to
learn Kotlin Multiplatform.

## Decision

- A KMP module `mobile/shared` holds everything that isn't UI: API client (Ktor), JSON models
  (kotlinx.serialization), business logic, later WebSocket, offline cache (SQLDelight) and token
  storage (`expect`/`actual`).
- **UI is fully native**: Jetpack Compose on Android, SwiftUI on iOS. (Not Compose Multiplatform:
  we want each platform to look and behave natively, and to learn Swift ↔ Kotlin interop.)
- Targets: `androidTarget`, `iosArm64`, `iosSimulatorArm64`, `iosX64`, plus `jvm` so the shared tests
  run on any machine/CI without an Android SDK or a Mac.
- The Xcode project is **generated by XcodeGen** from `iosApp/project.yml` and not committed. Text
  config is reviewable, and there are no `.pbxproj` merge conflicts.
- Wiring is manual (`MyChatSdk`); no DI framework until it's clearly needed.

## Consequences

- Screens are written twice (Compose + SwiftUI), and that's intended.
- Contracts are mirrored by hand in Kotlin (see ADR 0001).
- Building the iOS app requires macOS; everything else builds on Linux.
